## Project Overview

Apache Iceberg SCD2 (Slowly Changing Dimension Type 2) proof of concept using **Trino** as the SQL engine on **Apache Iceberg** tables, with **MinIO** for S3-compatible storage and **Hive Metastore** as the catalog. The Docker infrastructure is generated by [Platys](https://github.com/TrivadisPF/platys-modern-data-platform).

## Running Tests

Tests are integration tests requiring a running Trino instance (started via `docker/docker-compose.yml`).

```bash
source scd2/python/venv/bin/activate

# Required environment variables (local defaults)
export TRINO_HOST=localhost TRINO_PORT=28082 TRINO_CATALOG=iceberg_hive TRINO_SCHEMA=default
export TRINO_USE_SSL=false TRINO_USER=trino TRINO_PASSWORD=
export S3_ENDPOINT_URL=http://localhost:9000 S3_WAREHOUSE_BUCKET=warehouse-bucket S3_WAREHOUSE_PREFIX=warehouse
export AWS_ACCESS_KEY_ID=admin AWS_SECRET_ACCESS_KEY=abc123abc123

# Run a single test file
pytest scd2/python/test/test_scd2_ins.py -v --log-cli-level=INFO -s -vv

# Run all tests
pytest scd2/python/test/ -v
```

Python environment setup: `cd scd2/python && python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt`

## Architecture

### Core Library (`scd2/python/lib/`)

- **`scd2.py`** — Main SCD2 implementation. All operations execute as Trino SQL. Key entry point: `merge_into_dim_table()`.
- **`util.py`** — Trino connection helpers, SQL execution with metrics, DataFrame rendering, markdown report generation. Gracefully falls back from Dataiku DSS to environment variables.
- **`constants.py`** — Sentinel values (`MAX_TS = '9999-12-31 23:59:59'`).

### SCD2 Merge Flow

1. Raw data is inserted into `raw_person` (partitioned by `dp_loaded_at`)
2. A Trino view is created via `format_view()` containing CTEs that FULL OUTER JOIN raw against dim, compute SHA-256 row hashes, and classify records as `NEW`/`CHANGED`/`DELETED`/`UNCHANGED`
3. Changed records emit two rows: one with `merge_key=pk` (matches existing → UPDATE closes old version) and one with `merge_key=NULL` (no match → INSERT new version)
4. `MERGE INTO dim_person USING view_person_scd2` executes the SCD2 logic

### Key Design Patterns

- **View-then-Merge**: Intermediate view separates change detection from merge execution, enabling independent debugging
- **SHA-256 row hashing**: `concat_ws('||', ...)` + SHA-256 for change detection instead of column-by-column comparison
- **`merge_key = NULL` trick**: Standard Iceberg/Trino pattern for emitting both UPDATE and INSERT from a single changed record
- **`dp_is_active` vs `dp_is_latest`**: `dp_is_latest=TRUE` = most recent version (even if deleted); `dp_is_active=TRUE` = not deleted. Supports different query patterns
- **Delta mode**: `use_delta_mode_for_raw_table` flag controls whether absent entities are treated as deleted (full-snapshot mode) or ignored (CDC/delta mode)

### SCD2 Dimension Metadata Columns

`dp_valid_from`, `dp_valid_to`, `dp_is_active`, `dp_is_latest`, `dp_load_timestamp`, `dp_created_at`, `dp_replaced_at`, `change_type`, `record_hash`

### Test Structure

Each test file in `scd2/python/test/` follows this pattern:
- Module-level Trino connection opened on import (`conn = init_trino_connection()`)
- `test_step_1()` drops/recreates tables, inserts initial data, runs merge, asserts results
- `test_step_2()+` runs the specific scenario and asserts
- Shared helpers in `commons.py`: `scd2_merge_as_test()`, `scd2_merge_as_preparation()`, `scd2_sel_as_test()`
- Tests generate markdown reports in `scd2/python/test/reports/`

### Benchmarks (`scd2/python/benchmark/`)

Performance testing with synthetic data (Faker). T-shirt sizes (`xs`, `m`, `l`, `xl`) control dataset volume. Results stored in `iceberg_hive.default.benchmark` table, analyzed via `scd2/sql/benchmark_reporting.sql`.
